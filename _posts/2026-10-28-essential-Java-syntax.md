## 🟩 함수(메서드)에 변수나 배열 넘기기 (복사 호출, 참조호출)
함수를 호출할 때 넘기는 데이터를 인자<sup><strong>Argument</strong></sup>라고 하고, <br>
호출받은 함수에서 넘어온 인자를 받는 변수를 파타미터<sup><strong>Parameter</strong></sup>라고 한다. <br>
이정도는 알 것이다. 

함수 sample(x)를 호출한다고 했을 떄, 복사 호출은 **변수 x의 값**을 넘기고, <br>
참조 호출은 변수 x의 레퍼런스(식변자, 포인터 또는 주소)를 넘긴다. 


이때, **자바는 기본적으로 복사호출**이므로, 파라미터에 변수 x의 값을 복사해서 사용한다. <br>
따라서 원래 호출했던 곳에 있던 변수 x의 값은 변하지 않을 것이다. 

아래와 같이 파라미터의 값을 2배하는 함수를 살펴보자. 
````java
void twofold(int a) {
    a = 2 * a;
}
````

````java
int x = 5;
twofold(x);
````

이 코드를 살펴보았을때, 함수 twofold에 있는 파라미터인 a의 값은 2배되지만, x의 값은 변하지 않는다. <br>
x의 값이 ***복사***되어 함수 twofold에 전달되었기 때문이다.


하지만, 배열의 경우에는 말이 달라진다. 
자바의 배열 이름은 그 배열의 레퍼런스 값인 id, 즉 배열을 식별할 수 있는 식별자를 갖고 있다. <br>
즉, 함수의 인자로 배열 이름이 적히면 함수가 수행될 때 . 배열의 id값이 복사된다. <br>
id 값은 실제 배열이 있는 곳에 접근하게 해줄 수 있으므로, '배열 자체를 복사'하지 않아도 원래 배열에 접근할 할 수 있다.
본인이 C 언어의 포인터 개념을 학습해본적이 있다면 더욱 이해하기 쉬울 것이다. <br>

즉, 배열의 경우에는 결과적으로 **참조호출**을 하는 셈이다. 
물론 주소 또한 **복사**되어 함수에 전달되지만, 그 전달하는 데이터가 어떤 변수의 **값**이 아닌 **레퍼런스 값(주소)**이다. 
그냥 주소는 뭐 어떻게 전달되나 궁금할 수도 있어서 말해보았다. 

아래 배열의 요소의 값을 바꾸는 함수 코드 예시를 보자.
````java 
sampleAccess(int b[], int n) {
    b[n] = 8;
}
```` 

````java 
int[] a = new int[10];
a[5] = 7;
int k = 5;
sampleAccess(a, k);
````

sampleAccess 함수에서는 원래의 배열 공간에 접근하여 값을 수정하는 것이다. 
이 부분때문에, 우리는 다음과 같이, 
`a = sampleAccess(a, k);`뭐 이런식으로 값이 수정된 배열을 함수에서 다시 반환하는 식으로 코드를 짤 필요가 없는 것이다. 
또한 여기서 배열 공간이라는 말을 써서 헷갈릴 수 있는데, 
자바에서 배열명은 배열이 할당된 메모리 공간을 가리키는 id라는 사실을 다시 한번 더 상기시킨다면 이해하기 쉬울 것이다. 


## 🟩 대소 비교를 위한 인터페이스: Comparable 
자바에서 기초타입(int, float 등)끼리 대소 비교를 할때는 \>, \<, \<=, \>=, \= 이런 연산자를 사용한다. 
하지만, 기초타입 외에 클래스간에는 이런 상식적인 대소 관계가 존재하지 않는다.
따라서 객체 안에 객체끼리 비교할 수 있는 어떤 필드가 있어야하고, 그 필드를 비교해주는 내부 메서드가 정의되어 있어야한다. 


자바에서는 이런 경우를 위해서 ***Comparable***이라는 인터페이스 타입을 제공한다. 
Comparable을 따르는 클래스의 객체 a, b가 있다고 할 때, 다음과 같이 함(아래 코드 참고)으로써 a < b를 수행한 효과를 낸다.
이때 a, b는 Comparable를 따르는 어떤 클래스의 객체이고, 클래스 내부에 메서드 compareTo()가 정의되어 있어야한다.
`if (a.compareTo(b) < 0) ...`


또한 **인터페이스를 변수 타입으로 사용**할 수도 있다. 
예를 들면 클래스를 레퍼런스할 변수 a를 다음과 같이 선언할 수 있다(아래 코드 참고).
````java
Comparable a;
````
이렇게 변수를 선언하면, a는 어떤 클래스의 레퍼런스 변수인데, ***인터페이스 Comparable을 따르는 클래스로 제한한다***는 뜻이다.

그렇다면 마지막으로 이 Comparable이라는 인터페이스가 우리의 코딩에 어떻게 쓰이고 있는지 실제 코드를 참고하여 알아보자. 
실제 Comparable인터페이스 코드를 찾아본다면 다음과 같이 되어 있다.
````java
public interface Comparable<T> {
    public int compareTo(T o);
}
````

이 메서드 하나 있는게 전부이다. 
즉, 인터페이스 `Comparable<T>`를 따르는 클래스들은 제네릭 타입 T를 비교의 주체로 삼아 
`compareTo()`를 구현해서 정수를 리턴하라고 하는 것이 전부이다. 
이것이 그 많은 클래스들을 거느리고 있는 인터페이스 Comparable의 실체이다. 

아래는 이 Comparable인터페이스를 따르는 클래스이자 우리가 매우 자주 사용하는 `Integer`클래스 코드이다. 
````java
public final class Integer extends Number
        implements Comparable<Integer>, Constable, ConstantDesc {
    
    // (생략)
    public int compareTo(Integer anotherInteger) {
        return compare(this.value, anotherInteger.value);
    }

    public static int compare(int x, int y) {
        return (x < y) ? -1 : ((x == y) ? 0 : 1);
    }
    
    // (생략)
}
````
compareTo를 재정의하여 다음과 같은 반환값을 반환하도록 작성되어 있다.
- 0: 두 문자열이 완전히 같음
- 음수 (-): 기준 문자열이 비교 문자열보다 사전상 앞에 위치
- 양수 (+): 기준 문자열이 비교 문자열보다 사전상 뒤에 위치


서로 다른 클래스의 대소 비교를 할 상황은 가능은 하지만 평생 만나기 힘들것이고, 대부분 동일한 클래스의 대소비교를 할 것이다. 
이때, 해당 클래스에 대소 비교를 위한 메서드를 새로 만들 수도 있겠지만, compareTo메서드를 알고 있다면 이놈을 재정의 해서 사용하면 된다. 
반환값이 정수인 부분에서 불편하지 않을까라는 생각이 들었었는데, 대소비교하는 건데 결과로 정수로 알려주는 것이 처리하기 위함에 있어서 가장 깔끔하겠다는 생각이 들었다.
따라서 나는 사용할 상황이 온다면 앞으로 자주 사용할 것같다.
